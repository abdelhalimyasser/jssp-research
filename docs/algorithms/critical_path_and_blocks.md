## 1. Node-Weight Head/Tail Equations (`u64` Checked Arithmetic)

Every operation vertex $u \in O$ carries strictly positive node weight $p[u] > 0$, while `Source` and `Sink` carry weight $0$. All additions use `checked_add`, returning `JsspError::TimeOverflow` on `u64` overflow.

- **Head time `head[u]`** (longest path length from `Source` to $u$, **excluding** $p[u]$):
  $$\mathrm{head}[\mathrm{Source}] = 0, \qquad \mathrm{head}[u] = \max_{(v \to u) \in E} \big(\mathrm{head}[v] + p[v]\big)$$
  Operations with no non-boundary predecessors receive `(Source -> u)`, giving $\mathrm{head}[u] = 0$. Note this matches $r_u = L(0, u)$ in [`obr_decoder.md`](file:///home/abdelhalimyasser/Downloads/jssp-research/docs/algorithms/obr_decoder.md) and [`n5_n6_n7_n8_definitions.md`](file:///home/abdelhalimyasser/Downloads/jssp-research/docs/algorithms/n5_n6_n7_n8_definitions.md).
- **Tail time `tail[u]`** (longest path length from $u$ to `Sink`, **excluding** $p[u]$):
  $$\mathrm{tail}[\mathrm{Sink}] = 0, \qquad \mathrm{tail}[u] = \max_{(u \to v) \in E} \big(p[v] + \mathrm{tail}[v]\big)$$
  Operations with no non-boundary successors connect to `Sink`, giving $\mathrm{tail}[u] = 0$. Note this matches $q_u = L(u, \tilde{n}) - p_u$ in [`n5_n6_n7_n8_definitions.md`](file:///home/abdelhalimyasser/Downloads/jssp-research/docs/algorithms/n5_n6_n7_n8_definitions.md) (conversion from inclusive tail-to-sink distance $L(u, \tilde{n})$ is $\mathrm{tail}[u] = L(u, \tilde{n}) - p[u]$).

### Multi-Predecessor / Multi-Successor Ties
- `compute_heads` traverses topological order (`O(V + E)`), recording **all** immediate operation predecessors $v$ attaining $\mathrm{head}[v] + p[v] = \mathrm{head}[u]$ (sorted by `OperationId`), **all** maximizing incoming `ArcId`s, and `representative_predecessor = maximizing_predecessors.first()` (lowest `OperationId`).
- `compute_tails` traverses reverse topological order (`O(V + E)`), analogously recording all maximizing successors and `representative_successor`.

## 2. Graph Makespan Verification & Scope Limitation

Let:
$$C_{\max}^{\text{graph}} = \mathrm{head}[\mathrm{Sink}] = \mathrm{tail}[\mathrm{Source}] = \max_{u \in O}\big(\mathrm{head}[u] + p[u] + \mathrm{tail}[u]\big)$$

`analyze_disjunctive_graph` enforces exact agreement $C_{\max}^{\text{graph}} == C_{\max}^{\text{schedule}}$, returning `JsspError::GraphMakespanMismatch` on any discrepancy.

> [!NOTE]
> **Verified Equivalence Scope:** Every feasible schedule generated by M2's canonical `decode_obr` (active Serial SGS) or `decode_obr_append_only` (semi-active reference) satisfies $\mathrm{head}[u] == S_u$ and $C_{\max}^{\text{graph}} == C_{\max}^{\text{schedule}}$. An externally constructed feasible schedule containing unnecessary idle delays (non-semi-active right shifts where $S_u > \mathrm{head}[u]$ and overall makespan is pushed beyond $C_{\max}^{\text{graph}}$) is explicitly rejected with `JsspError::GraphMakespanMismatch` rather than silently accepted.

## 3. Critical Operations, Critical Arcs & Compact Critical Subgraph

For each operation $u \in O$:
$$\mathrm{slack}[u] = C_{\max}^{\text{graph}} - (\mathrm{head}[u] + p[u] + \mathrm{tail}[u])$$
- Any $\mathrm{head}[u] + p[u] + \mathrm{tail}[u] > C_{\max}^{\text{graph}}$ immediately returns `JsspError::NegativeOperationSlack`.
- $u$ is **critical** iff $\mathrm{slack}[u] == 0$.

For each directed arc $a = (u \to v) \in E$:
- **Operation-to-operation arc** (`JobPrecedence` or `MachineOrder`): critical iff **both** (1) head-tightness $\mathrm{head}[u] + p[u] == \mathrm{head}[v]$ and (2) $v$ is critical ($\mathrm{head}[v] + p[v] + \mathrm{tail}[v] == C_{\max}^{\text{graph}}$) — equivalently $\mathrm{head}[u] + p[u] + p[v] + \mathrm{tail}[v] == C_{\max}^{\text{graph}}$.
  > Merely having two critical endpoints ($\mathrm{slack}[u] = \mathrm{slack}[v] = 0$) does **not** make $u \to v$ critical when $\mathrm{head}[u] + p[u] < \mathrm{head}[v]$ (verified by explicit multi-path unit and integration tests).
- **`Source` boundary arc** ($\mathrm{Source} \to v$): critical iff $\mathrm{head}[v] == 0$ and $\mathrm{slack}[v] == 0$.
- **`Sink` boundary arc** ($u \to \mathrm{Sink}$): critical iff $\mathrm{head}[u] + p[u] == C_{\max}^{\text{graph}}$ and $\mathrm{tail}[u] == 0$.

### Compact Critical Subgraph & Representative Path
- **`CriticalSubgraph`** stores `Source`, `Sink`, all critical `OperationId`s in canonical `(job, op_index)` order, and all critical `ArcId`s partitioned into `critical_arcs`, `critical_operation_arcs`, `critical_job_arcs`, and `critical_machine_arcs` in `O(V + E)` without enumerating exponentially many paths.
- **`RepresentativeCriticalPath`** reconstructs one deterministic `Source`-to-`Sink` longest path by starting from the lowest `OperationId` in `sink_maximizing_predecessors` and repeatedly stepping backward via `representative_predecessor` (lowest `OperationId` among maximizing predecessors) until reaching `Source`, verifying `sum(p[u]) == C_max`. When multiple equal-length critical paths exist, non-selected branches remain represented in `CriticalSubgraph` and `OperationCriticality::maximizing_predecessors`, even when critical operations do not lie on the representative path.

## 4. Critical Block Extraction

In M4 (`crates/jssp-core/src/graph/critical_blocks.rs`), a **critical block** is defined over all critical `MachineOrder` arcs in the critical subgraph:
- Scan each machine $m \in \{0, \dots, M-1\}$'s chronological `machine_order_arcs[m]` in `O(V + E)` total time.
- Group every **maximal contiguous run** of critical `MachineOrder` arcs $(b_1 \to b_2 \to \dots \to b_k)$, yielding block operations $[b_1, \dots, b_k]$ of length $k \ge 2$.
- Adjacent critical operations ($\mathrm{slack} = 0$) separated by a non-critical `MachineOrder` arc are never merged into one block.
- Each `CriticalBlock` records `id: CriticalBlockId`, `machine`, `operations`, `first_operation`, `last_operation`, `len >= 2`, and `critical_machine_arcs`.

*(Note for M5: `N5`–`N8` neighborhood generation in [`n5_n6_n7_n8_definitions.md`](file:///home/abdelhalimyasser/Downloads/jssp-research/docs/algorithms/n5_n6_n7_n8_definitions.md) may project onto a single representative critical path or use graph-wide blocks per the frozen M1-B definitions; M4 implements zero neighborhood moves.)*

## 5. Complexity Summary & Limitations

- **Time & Space:** $O(V + E)$ for head DP, tail DP, slack/arc classification, critical subgraph construction, representative critical path reconstruction, and critical block extraction; $O((V + E) \log V)$ for deterministic topological sort. Because $|V| = L + 2$ and $|E| = O(L)$, overall memory is linear $O(L)$.
- **Remaining Limitations:**
  - Verified equivalence $C_{\max}^{\text{graph}} == C_{\max}^{\text{schedule}}$ applies to semi-active/active schedules (e.g. M2 Serial SGS); artificially right-shifted schedules raise `GraphMakespanMismatch`.
  - No neighborhood move generation (`N5`–`N8`) or inverse DAG-to-OBR adapter (`D01-B`) is implemented yet (Milestone M5).
